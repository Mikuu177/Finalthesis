## 第 2 页：Evaluation Normalization 页（v1.1）

### 为什么要做 ruleset v1.1
- gold 存在多格式混用：`MM-DD-YYYY / M/D/YYYY / H:MM / HH:MM / Month-Year / MonthYear无分隔 / TZ压缩串`。
- 若直接 strict 字符串比较，会把“语义等价答案”误判为错（典型是 TZ 与 Date）。

### v1.1 修复了什么
- Date：`MM-DD-YYYY / M/D/YYYY / YYYY-MM-DD / Month-Year / MonthYear(无分隔)` 等价匹配。
- Hour24：`H:MM` 与 `HH:MM` 等价。
- TZ：`xAM/PMon...` 转 `HH:MM` 后匹配。
- Month Shift：`July` 与 `YYYY-MM` 按月份等价。
- Year Shift：整数归一匹配。

### Base vs Corrected 的含义
- **Base**：原始 strict 字符串口径（保留审计价值）。
- **Corrected**：按类别归一规则复核后的口径（正式展示口径）。
- 重要声明：**原始数据未改，只修评分层**，因此可追溯、可复现。
